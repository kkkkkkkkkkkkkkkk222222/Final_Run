# FinalRun1 运送与门口脱困（2026-11-22）

配套上位机为 `28deaa6861c0208adf4b00c125d213c687bd2a95`。从普通正式载荷的 STAGE NAV 开始，旧协议的 D=0 结束预备点移动。送完的抬升、退出和收回机构走原流程，随后在原上位机指定的第一条空车换站命令中归中、退回场心、侧移到原①或③。暂存、扫障、找回和上位机要求的门前补位仍走各自入口。

| 情况 | 车的动作 |
|---|---|
| 带货去程 | 远处用旧上位机的方向和剩余距离对齐本段场地坐标原点，随后用轮式里程计跟踪。依起点选先横移或先纵移，保持车头；受阻的外侧穿越会多退到黄块以下再横移。进原绿框后服从上位机到点。 |
| 当前朝向放不进窗口、或入窗后转正会扫到黄块 | 先检查整车原地转动需要的半径 240 mm。当前位置有净空就停车转正；否则在原航向下平移到可达空位再转。只在普通带货 STAGE 内进行。无法找到可行空位时停止平移，保留未完成状态；位置或航向明显变化后可重新求路。 |
| 速度 | 预备点粗移最高 800 mm/s。进入 180 mm 精定位范围，速度请求下限 400、上限 600 mm/s，当前距离增益在该范围通常给出 400。拐点和净空不足时单独减速。门口相机横移维持 270～400 mm/s。 |
| 侧边被卡 | 有平移输出且同方向连续 400 ms，轮式里程计投影进展小于 8 mm 时尝试一次。车往中线和己方围栏斜移，每轴最多 50 mm，退让速度最高 180 mm/s。视觉阶段为原绿框前沿及中线侧各留 10 mm，再用黄块净空裁短等长两轴。可用行程不超过 5 mm 时停住。 |
| 退让后 | 到达或 650 ms 到期后结束退让。完全未动或再次持续受阻就停止该方向输出，位置变化或新的方向允许继续，重复包不追加一次斜移。PAUSE、HOLD、视觉改向、D=0 沿用现有控制权。正式 ENTER 盲走和盲推沿用原流程。 |

## 实际离线检查

- 使用冻结上位机的 `_navigation_command`、到点判断和 `SearchTransferRoute.payload` 驱动原生 C 任务入口。每 20 ms 回送理想位移及转角，检查 DONE 与 D=0 一致。28 条名义轨迹（五个起点、双方、两类目的地、返两站）和另加的红方左半区 35 条朝向轨迹通过。20 条需要提前转正。
- 在本机导出的场地及闭爪前端零位模型上，用 motion-sim-bridge main `8bebe33` 对每段平移做连续碰撞检查，对转动按至多 1° 采样，包括到门口后的转正。63 条轨迹均无固定物硬接触。红方第④例的实际离线折点约为 (-650,306)、(-82,306)，而原直达推算会碰右爪。地上可动物、实车抬爪姿态、载荷凸出、轮胎打滑和定位误差不在碰撞通过结论内。
- 独立故障注入覆盖红蓝与左右镜像、每轴 50 mm、裁至 12 mm、绿框无余量、持续完全堵死、正常运动、改向、暂停、精定位 400 和 D=0 优先。原协议帧级回归复核审核、分离、开爪退出、换站、侧挤与扫障入口。
- 本轮只构建。实际烧录、板端身份、行驶轨迹和实车制动距离待场测。
