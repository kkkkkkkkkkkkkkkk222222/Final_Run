## 2. 上位需接续的策略修改

### A. 先判整批合法，再决定分离侧

保留首件前的单绿资格。首件后先用完整真实载荷判断：纯绿/黑1～3件或单伤员合法，直接抓取/运输；只有不合法批次才进入分离选择。抓前、抓后和运输复审使用同一选侧业务规则，动作入口沿各自现有流程。

当前main已具备多件材料及非空搬移语义，可作为数量逻辑起点；联调3829156中的单件门槛不能整段带回来。需要同时处理 `_audit_valid`、`_side_is_legal_for_task`、合法侧候选、已确认载荷复用、mode43扫障及mode45原货找回，避免只改主入口。

### B. 选侧优先级与锁定

| 场景/题号 | 应有结果 | 当前差异所在 |
| --- | --- | --- |
| G03、S01～S03 | 无有效旧锁定、需要选侧时，单伤员优先，核心其次，普通再次 | `_post_first_preferred_keep_side` 当前材料按绿数优先 |
| G05、S05 | 原锁定左侧单绿仍可保留时，不因右侧新出现单伤员就切换；原侧不再满足该场景候选条件才重选 | 锁定只作为同级平局规则，侧别投票会覆盖旧锁定 |
| G04、O03～O05 | 橙绿/橙黑混装对侧为合法单绿或单黑时，保对侧合法单件 | 当前优先保混装伤员侧 |
| O06 | 无旧锁定时，左橙绿、右橙黑保右；镜像相反 | 当前混装候选默认取左，没有橙黑优于橙绿的规则 |
| G06、G07 | 同级、同数量、同可分离性时，先原锁定侧，否则左；镜像规则对称，固定平局方向除外 | 沿用原有效平局行为 |
| B03～B05 | 纯净合法侧优先于对侧混蓝的可试分侧 | 当前相应结果已一致，不应被新排序反向破坏 |

同步核对 `_preferred_keep_side`、`_observe_disperse_side_vote`、`_choose_release_side`、`_prefer_green_batch` 和 `_audit_destination`。不能只改返回侧别，而仍把选中批次、目标类别、伤员/材料目的地或后续“想保留的类别”写回绿色。低位只执行给定保留侧，不重新对颜色排序。

### C. 特殊试分与总次数

1. **B06/B07：同侧橙蓝或绿蓝、另一侧空**。只允许一次物理试分；完成后真实审核若得到该阶段可运输的目标就继续，否则整批放弃。不是沿原“连续两次无进展”再试。
2. **B08：两侧都混蓝**。题中左橙蓝、右绿蓝及其镜像直接整批放弃，不先保绿蓝侧试分。
3. **O09：同侧各一橙、一绿、一黑，另一侧空**。第一次分离后没有物体分出就整批放弃；有物体分出可继续，总计最多3次。剩单橙或绿黑两件时属于合法载荷，直接按对应目的地运输。
4. **R01/R02/R04/R06/R07**。全批最多3次，换侧和进展不补充预算；原已接受动作重复不增加次数。每次动作完成后消费真实新复审，合法就结束分离，非法且达到上限才放弃。夹持档位沿本批进度，不因换侧回到第一次强夹档。
5. **R03**。用户以目标仍在且非目标物实际减少来判进展；不要沿旧代码把“新出现绿色”直接当作恢复次数的理由。进展只决定O09是否继续等业务分支，不能再重置总预算。

主要入口为 `_count_separation_acceptance`、`_review_separation_result`、`_separation_limit_reached`、`_start_danger_release`、`_start_disperse` 与 `_start_capture_abandon`。现有 `disperse_limit=2` 和 `reviewed-progress` 差值判断需同步改为本批总上限3，并保持“完成后复审”的原交接时点。无需新增计时、新鲜度门、握手或协议字段。

### D. 普通抓取转暂存

F07不能只改目标颜色。首件前真实审核为该橙黑组合时，应转入现有搬堆角色，复用搬堆放置点、释放和回搜索路径；同步 `initial_stash`/目的地、审核角色、导航与释放上下文。不得走正式投送完成登记，不得设置首件或伤员搜索轮次。

当前已有 `settings.stash_point`、`INITIAL_STASH_NAV` 和相关返回流程。接收方应在自己的当前开局策略下复用这些实际入口，避免另造放置点或把一次搬移误触发成新的完整开局。

### E. 归属不明、数量纠正及漏框

- U03：审核物体的左右归属确实不明确时，先走原无侧观察，不能通过框中心兜底强行当作可靠侧别。核对 `capture_side_for_bbox` 两侧同时成立的分支，以及 `make_vision_snapshot` 中 `capture_side or centre` 的补判；保留真实物体在总数内。
- U04：只有确认所有物体已明确归侧、左右组成完整而总数字段不一致，才按左右合计纠正。未归侧、遮挡、协议每侧计数溢出都不能用该规则把真实物体抹掉。低位仍接收真实、格式正确的现有审核帧。
- U05：对实际收到且有效的当前画面，按本帧可见载荷判断，去掉 `HeldCargoEvidence.missing_incompatible` 把历史伤员/蓝块补回当前审核的行为。缺图不等于零件，不把历史物体伪装成当前检测。同步检查闭爪、运输及扫障找回的审核构建和载荷复用路径。
- U06：仅保留已有绿蓝近侧特例及其真实来源帧/角色，不新增其他目标特例。
